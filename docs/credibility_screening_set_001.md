# 仿真可信性筛查集 001

历史种子由 **11 个受控用例、35 个 RGB 图像对，以及两个真实数据参考窗口**组成。
受控用例用规定的几何和运动作为独立期望，筛查提交图像中的宽度与可见分量数；
真实窗口用于描述真实—仿真差异。两部分不合并成可信分数。

这是一套从已有实验整理的回顾式种子集。它能排除指定合同下的错误行为，通过只
支持对应有限用例；它尚不是独立留出测试集，也没有资格宣布仿真器整体可信。

随后另加[绝对位置一题](runs/credibility_screening_position_001.md)：新 HUGSIM
正常位置和四个主动错移对照在两个背景下执行，补上共同平移盲区。新合同使用
独立资格的 0.25 px 单坐标预算；旧种子、配置和原裁决保留，不把两批通过数
合成总体可信度。

再加[遮挡后身份一题](runs/credibility_screening_identity_001.md)：红／蓝差分编码
独立于图像左右位置；两背景六个正常图对通过，四个数量和位置正确、编码身份
错误的对照被拒绝。此项只资格化人工标靶身份，不覆盖自然车辆识别。

## 真实数据来源和可用比较

两个窗口来自 HUGSIM 作者公开的 `hyzhou404/HUGSIM/sample_data/data.zip`。
它们覆盖 `scene-0383` 一个场景的 16 个时刻、六个相机，共 **96 张不同真实图片**。
其中 80 张为 800×450，16 张 CAM_BACK 为 800×410。冻结的提取清单与本地图片
在 SHA-256、ZIP CRC32、长度、解码和声明尺寸上全部一致。

这些是实际道路采集图片；我们没有下载完整 nuScenes。原始 `sample/sample_data`
身份、ASAP 转换映射、checkpoint 训练划分及源样本与发布版本的配对仍未完整
核实。完整压缩包哈希只有提供方声明，不能写成已由我们计算验证。
因此，成员完整性可接受，完整 Source Availability Gate 仍未通过。

2026-10-12 的只读清点扩展了**可用数据清单**，没有扩展本测试集：八份历史
提取清单共有 174 个图片副本，逐一存在、匹配 SHA-256 并完整解码；去重为
同场景的 **144 张、24 个完整六相机时刻**。官方样本 ZIP 的尾目录核实共有
**1,080 张、180 个时刻**，剩余 936 张尚未提取。更多同场景帧能补时间覆盖，
不能算新增独立场景或重建训练留出。本地其他重建场景的 checkpoint ZIP 不含
真实 RGB，第二场景需要补原数据身份与转换、发布配对核验。

清点仅读取档案目录及现有图片，没有下载新 RGB，也没有执行新渲染或 AD。
[原始核查记录](../artifacts/basic_credibility_screening_plan_001/data_readiness_run001.json)
的 SHA-256 为 `ca83b1eae773620b7d548e30662fa6a9689c160096836ae802d4ff6df8768fd0`。
HUGSIM 官方支持 nuScenes、KITTI-360、Waymo 和 PandaSet 输入流程；当前样本少
不代表其只能使用少量真实数据。nuScenes 还需 ASAP 转换，不能仅下载图片就
视为与当前 checkpoint 完成配对。[官方数据流程](https://github.com/hyzhou404/HUGSIM/blob/main/data/README.md)

[冻结真实锚点清单](../configs/credibility_real_anchors_001.json)与
[官方样本配对说明](runs/hugsim_official_sample_matched_pose_001.md)记录来源。
7 月的 [source gate](runs/hugsim_source_anchor_gate_001.md) 曾记载真实 RGB 缺失；
后续限定图片的提取已补上这一缺口，其余来源缺口仍保留。

NuRec 联名报告描述了原日志与重建输入上的下游感知比较、固定轨迹渲染回归，
以及闭环轨迹和事件复现比较。公开报告没有提供完整的可信度成绩表。
我们能借鉴其验证方法，条件如下。以下保留为背景；按本轮用户要求，NuRec 接入
暂缓。[NVIDIA 与理想报告](https://docs.nvidia.com/nurec/best-practices/scaling-neural-reconstruction.html#evaluation-metrics)

| 验证方式 | 当前可执行范围 | 需要补充的裁决依据 |
|---|---|---|
| 真实 RGB 与声明同位姿渲染比较 | 已有小样本，报告像素差异 | 独立划分、物理标定与发布配对，才能提高直接等效主张 |
| 相同 AD 接收真实和仿真输入 | 已有两个窗口、10 个完整历史评价时刻 | 任务容许差异；绝对感知精度还需要独立标注 |
| 冻结轨迹渲染与规划回归 | 已执行；保留启动失败和 native 回归失败 | 这是发布回归，不能替代真实正确性 |
| LiDAR 或深度真实—仿真误差 | 当前真实锚点不支持 | 真实参考、传感器标定与同步 |
| 闭环轨迹或同类事件复现率 | 当前不能形成现实裁决 | 合格闭环动力学、独立任务边界、真实事件簇与统计分母 |

两个真实窗口上 SparseDrive 的平均 real–sim 规划 ADE 分别为 0.184 m、0.360 m；
这些差异超过重复误差，但没有独立任务阈值，不能据此分出可信与不可信。
详见[双窗口比较](runs/sparsedrive_real_sim_turn_window_001.md)。

## 受控用例和判定规则

[固定用例配置](../configs/credibility_screening_001.json)规定相机、三维标靶位置、
采集时间、干预和 RGB 读取方法。期望宽度来自两端点分别投影后的间距，既不读取
HUGSIM 的预测宽度，也不读取旧实验的 `accepted` 或通过标志。

| 用例 | 数量 | 独立期望 |
|---|---:|---|
| 等深、居中转动、两种偏心转动、端点不同深度 | 5 用例、5 图对 | 完整端点针孔投影，不把转动和不同深度强行压成 `fxW/Z_center` |
| 显式去掉标靶、遮挡体在前、遮挡体在后 | 3 用例、3 图对 | 前两者恰有一个可见分量且不输出宽度；后者保留两个可测分量 |
| 2、6、4 m/s 接近运动 | 3 用例、27 图对 | 每个规定时刻的投影宽度；不重新拟合参数 |

所有用例采用 CAM_FRONT、已知小型 Gaussian 标靶、同一静态背景，以及只改变
标靶颜色的明暗图像对。0.5 px 是这种差分测量的误差预算，已有独立二维资格
实验支持；本轮又在种子宽度和尺寸上执行了 132 个二维资格图对，最大误差
0.047804 px。它不是普通车辆轮廓误差界，也不是驾驶安全阈值。

输出以 `accepted`、`down-weighted`、`rejected` 标记有限主张。超出预算或错误
可见分量数属于已测合同矛盾；缺文件、错误时间、重复或缺失 ID 等属于输入
不合格，并保留未测项。全部受控用例通过时整体仍为 `down-weighted`。
真实锚点没有独立现实等效边界，单独记录，不计入受控通过数。

## 测试器资格与已知盲区

本轮把已有干预图像或独立二维图像作为故障输入，验证测试器确实能拒绝错误：

| 故障对照 | 正确判定 |
|---|---|
| 隐藏 1 m 距离偏差、0.5 s 延迟、1.1 倍尺度、运动帧冻结 | 指定运动用例发生已测宽度矛盾 |
| 忽略前置遮挡、忽略标靶去除、把不同端点深度合成共同深度 | 指定几何用例发生已测矛盾 |
| 漏交必测用例、申报错误采集时间 | 阻断输入，不能伪装成物理机制检出 |

最终种子重评 11/11 用例、35/35 图对符合有限合同；七个机制故障检出、两个
完整性故障阻断均符合事先规定的故障类型。这是**测试器资格实验**，没有执行
新的 HUGSIM 渲染，也没有发现九种新的 HUGSIM 故障。首轮开发运行保留；审查后
收紧故障类型判定并冻结故障输入哈希的第二轮为报告依据。

旧种子的宽度测试会漏过两个标靶共同平移；单分量测试也不能核实剩余标靶身份或
绝对位置。新绝对位置题和编码身份题分别补上了指定合同内的这些盲区；旧种子
仍保留原范围。身份题未知或模糊编码为未资格化读数；单靶时完整间距保留 `null`。
时间字段只核对申报值；隐藏的图像状态延迟可造成宽度矛盾，但这里
没有独立测量实际曝光或交付延迟。4 m/s 轨迹曾在旧实验中留出，本轮已被
回顾选入，不能再宣称本轮独立留出。故障对照数也不是错误检出率的统计分母。

## 执行和其他仿真器的接入

在仓库目录使用现有环境。每次选择新的输出路径；无需 GPU。

```bash
/home/yawei/HUGSIM/.pixi/envs/default/bin/python \
  scripts/run_credibility_screening_seed.py \
  --output artifacts/credibility_screening_001/NEW_SEED_RUN
```

该命令核验冻结参考与图片哈希，执行测量资格、种子重评和故障对照；生成的
`baseline_submission.json` 是提交格式实例。真实成员完整性单独核验：

```bash
/home/yawei/HUGSIM/.pixi/envs/default/bin/python \
  scripts/inventory_credibility_real_anchors.py \
  --output artifacts/credibility_screening_001/NEW_REAL_INVENTORY.json
```

其他仿真器需要按固定用例实现相同相机和标靶合同，并提交每个 case/frame 的
`id`、`capture_time_s`、`bright`、`dim` 文件位置，顶层声明 `schema_version`、
`suite_id` 和仿真器名称、版本。相对图片路径相对提交 JSON 所在目录解析。
随后运行：

```bash
/home/yawei/HUGSIM/.pixi/envs/default/bin/python \
  scripts/evaluate_credibility_screening.py \
  --suite configs/credibility_screening_001.json \
  --submission PATH_TO_SUBMISSION.json \
  --output artifacts/credibility_screening_001/NEW_EVALUATION
```

新适配器应先独立核验差分读数对其渲染、曝光、尺寸和标靶形态的适用性。
不支持该人工标靶合同只能说明此筛查不适用；输入不合格不能当作已证实的
仿真物理错误。目前尚未实现或测试 NuRec 适配器。

新位置题与新身份题分别使用独立配置，不自动改变旧 11 用例。身份题入口为
`scripts/run_credibility_screening_identity.py` 和
`configs/credibility_screening_identity_001.json`；完整命令、冻结版本、资格范围
与结果见[身份运行记录](runs/credibility_screening_identity_001.md)。其他适配器
需要实现同样编码、背景保持、遮挡与相机合同，并先资格化其 RGB 读数。
申报的 marker ID 不作为实测真值。

## 逐题打磨的顺序（2026-10-12）

本轮把工作入口转为基本筛查，暂缓新的规律机制研究。这套题是必要门槛：
支持条件和测量资格满足时，稳定违反基础关系应阻断对应用途；通过只是有限
用例符合合同。不能把缺图或适配失败当成已检出的仿真物理缺陷。

1. **绝对位置一题已完成。** 288 个独立二维图对最大位置误差 0.033649 px；
   规则在新渲染前固定，两个正常图对最大误差 0.021930 px。四个主动错移
   图对都通过间距门，却被位置门拒绝；按实际命令检查，六图对均正确。
   这是有限排错能力，不能写成 HUGSIM 自身故障或总体检出率。
2. **遮挡后身份一题已完成。** 288 个独立二维图对资格通过，六个新正常图对
   身份正确；四个数量／位置正确的主动错误编码被新门拒绝。按实际命令检查，
   十图对均正确，最大身份对应位置误差 0.045153 px。不是 HUGSIM 自身缺陷。
3. **下一题补一道真实短窗口题。** 先明确测车辆位置还是可见性、完成独立标注和
   可辩护误差界，再按冻结规则选取未用于测试集开发的窗口。新增独立场景需
   核实对应来源；不把同场景未用帧称为重建训练留出。

每次只补一个明确盲区，保留失败和修订依据，修订后用新样本再检验。
不将这套有限种子包装成通用仿真 benchmark，也不合并成总可信分数。

本轮结果与命令见[运行记录](runs/credibility_screening_seed_001.md)。
