# HUGSIM 运动成像标靶实验 001 预注册

2026-10-11。用户已要求参考 NVIDIA／理想的做法继续实际实验，本轮将此前
“只定配置”的停止点推进到有界测量执行。执行前冻结本文件、配置和分析脚本；
不改动既有实验裁决，不接 AD，不安装 NuRec，不训练或下载场景。

## 主张与借鉴依据

[NVIDIA／理想联名报告](https://docs.nvidia.com/nurec/best-practices/scaling-neural-reconstruction.html#pre-simulation-evaluation)
描述了固定轨迹的渲染回归检查；其
[一致性部分](https://docs.nvidia.com/nurec/best-practices/scaling-neural-reconstruction.html#consistency-in-simulation)
强调确定性、输入时间与预处理。本实验借鉴隔离变量和重复对照的做法，具体标靶
和判据由本项目设计，不是复现理想的验证系统。

合同：`S` 为本机 pinned HUGSIM 的 `Camera → render → gsplat → RGB` 路径；
`T` 为规定运动的图像信息传递；`Ω` 为单相机、无遮挡双标记、2 秒设计网格；
`A` 不适用；`I` 为已知轴向偏差、信息年龄和横向尺度；`Y` 为两个标记的 RGB
质心间距及 0.5 秒有限窗对数增长率；`Θ` 为下列网格；`ε` 为分析器的设计
误差预算，不是驾驶任务容许误差；`R` 为双标记已知三维坐标和独立 CPU 投影；
`Req` 为身份、输入执行、测量资格、重复性和留出预测。

最强允许结论：**在冻结合同下，HUGSIM 渲染路径对已知标靶的内部成像规律与
条件预测一致。** 不包括普通车辆轮廓精度、现实相机资格、AD 使用这些线索、
时钟调度正确性或现实驾驶任务边界。

## 输入和测量

- 先查 CF-M nominal 的 `t=0–2 s` 原始 CAM_FRONT、保存位姿和时间。旧图只作
  可测量性筛查；无独立三维坐标的车灯/车身特征不用于定量公式裁决。
- 新实验使用 scene-0383 元数据首帧 CAM_FRONT 的原始 800×450 内参和位姿。
  它与旧 CF-M 的模拟相机参数分别记录，不暗示二者完全相同。
- 两个球形 Gaussian 标记中心间距 1.6 m，等深、姿态固定；标准差 0.035 m。
  测的是**可见特征的质心间距**，不是 Gaussian 包络或车框轮廓。
- 同一几何各渲染一张亮标记和暗标记图，背景、opacity、尺度不变。对原始
  uint8 RGB 做绝对差，阈值 8/255，连通域须恰有两个、面积各至少 3 px 且不触边。
  以差分亮度加权质心取水平间距，不向测量器传入预测位置或投影真值。
- 分别测试黑背景和已有 scene-0383 静态重建背景；保留后者原有 affine、地面和
  背景，仅不加载原生动态目标。标记通过 HUGSIM 的动态目标变换接口送入渲染。
  亮暗配对是专用标靶测量手段，不声称普通道路视频可做同样的消背景。
- CPU 资格化以独立二维 Gaussian 生成已知位置标记，覆盖配置中的宽度、子像素
  相位、大小和对比度，背景包括黑色及旧 CF-M RGB。事前宽度误差预算为
  **0.5 px**；只声明有限设计网格的实测资格，不把网格最大值当全域严格上界。
  缺失、触边、多余标记应被拒绝。资格不通过就停止 GPU 主实验，不放宽阈值。

## 冻结设计

精确数值见 [配置](../../configs/motion_observation_probe_001.json)。
采样 0.25 s，时域 0–2 s，有限差分窗 0.5 s。识别用 `Z0=24 m`、接近速度
2/6 m/s；留出用 `Z0=28 m`、4 m/s。每组 9 帧。

六种条件：无扰动、轴向 +1 m、信息年龄 0.5 s、恒定尺度 1.1、
`k(t)=exp[0.12 sin(πt)]`、以及 +1 m 与 0.5 s 联合扰动。延迟用显式早期
目标状态表示；负采集时刻有解析轨迹前史，不复制首帧。静态背景固定源时间 0。
此举**不测真实渲染延迟或系统排队延迟**，也不把墙钟耗时当物理延迟。

全部 324 个亮暗图对，加上两个背景下 slow baseline 各一次 9 帧重复：
342 对、684 张新 RGB 渲染。两次重复检查的是同一进程内同一输入。

## 预测与裁决

已知注入的预测在渲染前写出：`p=fWk/[Z(t-δ)+b]`。
使用 RGB 实测间距检验绝对投影误差是否 ≤0.5 px，并由每帧 `p±0.5 px`
推导同窗增长率区间。不能因增长率通过而忽略恒定尺度偏差。

联合扰动另用两个识别速度各自的 `median(fW/p−Z)` 解出共同 `b,δ`。
各帧的 `p±0.5 px` 给出等效深度偏差区间；同速各帧求交，两个速度联合成
参数集合。识别参数和区间先保存，再渲染留出组，后者不重新拟合。
留出逐帧检验预测加测量误差后的覆盖，记录中心预测残差，不只报告区间覆盖。
若识别集合为空或留出不覆盖，保留失败；不增加自由参数解释输出。

每个背景分别报告：测量成功率、最大绝对宽度/增长率残差、重复 RGB 最大差、
注入条件相对无误差模型可区分性、参数估计、留出覆盖。无观测不得当通过。
预期恒定尺度改变绝对宽度但基本不改变增长率；时变尺度改变增长率。
一个速度下距离/时间混淆，两个分离速度及第三速度留出检查条件识别。

整体 segment 至多 `down-weighted`，因为人工标靶资格不能自动转移给真实车辆
与现实相机。必要门通过时可将相应窄主张标记 `accepted`；不支持的强主张
`rejected`，并按仓库规则记录理由及独立诊断。测试失败不自动等于 HUGSIM 缺陷。

## 运行与留存

一个命令执行资格化、GPU 渲染、识别和留出分析：

```bash
env CUDA_HOME=/usr/local/cuda-12.1 TORCH_CUDA_ARCH_LIST=8.9 \
  PATH=/usr/local/cuda-12.1/bin:$PATH \
  /home/yawei/HUGSIM/.pixi/envs/default/bin/python \
  scripts/run_motion_observation_probe.py \
  --config configs/motion_observation_probe_001.json \
  --output artifacts/motion_observation_probe_001/run001
```

GPU 命令使用获准的 GPU 可见环境。输出目录必须不存在；保存环境、Git 状态、
输入/脚本哈希、原始成对图像、逐帧测量、冻结识别参数、图表及状态日志。
大产物留在 `artifacts/`；紧凑结果和报告进入版本控制。
