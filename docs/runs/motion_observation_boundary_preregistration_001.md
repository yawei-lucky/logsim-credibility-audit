# HUGSIM 运动成像适用边界实验 001 预注册

2026-10-11。用户授权继续执行当前条件下有意义的验证实验。本轮承接
[运动成像标靶实验 001](motion_observation_probe_001.md)，专门检查其简化等深宽度
模型什么时候失效，以及 RGB 分析器在目标特征不可见时能否停止输出数值。

## 主张范围

合同中的仿真器和接口为 pinned HUGSIM `Camera → render → gsplat → RGB`；任务是
已知双标记的投影测量；范围为 CAM_FRONT、三档中心深度、两种背景、五种标记
几何、一个明确缺失对照，以及同一遮挡体在目标前后的成对干预；不接 AD。参考为
预先给定的三维标记中心、相机内参和独立
CPU 针孔投影。误差预算沿用已经资格化的 0.5 px，不按本轮结果调整。

最强允许结论为：在本轮设计网格内，完整三维点投影能预测可见双标记的 RGB
质心间距；简化公式只在各自前提满足时可用；一个标记明确缺失或被规定遮挡时，
分析器只因恰好剩一个标记而返回不可测。结论不覆盖车辆轮廓、现实相机、系统
时延、AD 或驾驶任务。

## 冻结几何

精确数值见[配置](../../configs/motion_observation_boundary_001.json)。固定 CAM_FRONT
原始 800×450 内参和 metadata 首帧位姿，中心深度为 16/24/32 m。两个球形标记
中心间距 1.6 m，标准差 0.035 m；空背景和 scene-0383 静态重建背景分别执行。

| 条件 | 三维几何 | 目的 |
|---|---|---|
| `equal_depth` | 两点横向 ±0.8 m、同深 | 正对照；完整投影与 `fx W/Z` 应同时成立 |
| `left_marker_missing` | 与正对照同几何，但左点 opacity 固定为 `1e-6` | 分析器负对照；要求明确报告只找到一个标记 |
| `yaw_45deg_center` | 居中线段绕相机竖轴转 45° | 分离朝向导致的横向投影缩短 |
| `yaw_plus45_offset3m` | 中心右偏 3 m，竖轴转 +45° | 令两个端点深度不同，检查逐点透视投影 |
| `yaw_minus45_offset3m` | 中心右偏 3 m，竖轴转 −45° | 保持共同深度近似预测相同，同时反转深度次序 |
| `depth_skew_12m` | 横向仍为 ±0.8 m，左右深度相差 12 m | 强制检查同一深度近似 |
| `left_marker_occluder_behind` | 等深标记；在左标记同一像素射线上后置 2 m、σ=0.45 m 的高不透明 Gaussian | 遮挡干预正对照；仍须测到两个标记 |
| `left_marker_occluder_front` | 同一遮挡体沿同一射线移到左标记前 2 m | 检查特征不可见时是否停止给宽度 |

遮挡物在亮/暗图对中保持同一颜色、位置和 opacity，不参与差分目标。后置条件
深度必须大于左标记，前置条件必须小于左标记；两者的 CPU 投影中心均须与左标记
对齐至 `1e-9 px`，否则遮挡条件无效。
Gaussian 遮挡只是受控渲染输入，不代表现实车辆遮挡模型。

缺失控制必须按 `equal_depth → left_marker_missing → equal_depth` 顺序执行。第二次
正对照与第一次的两张 RGB 必须逐像素一致，确认临时 opacity 已恢复，状态没有
泄漏到后续条件。这个控制只资格化拒绝逻辑，不替代物理遮挡实验。

## 测量与资格

沿用 001 的原始 RGB 差分方法：亮、暗两个版本只改变双标记颜色；阈值 8/255，
连通域必须恰好两个、面积至少 3 px 且不触边，宽度为差分亮度加权的横向质心距。
测量器不读取 renderer 的 `means2d`、semantic 或 depth。

执行 GPU 渲染前，以独立二维 Gaussian 生成器覆盖 20–75 px 间距、四档子像素
相位、五档大小、两档 opacity，以及黑色和确定性纹理背景，共 720 个图对。
另按实际内参、横向位置、逐点深度和不同投影 sigma 生成 30 个几何对照，总计
750 对。最大误差须不超过 0.5 px；单标记必须精确以 `found 1`、多标记以
`found 3`、触边以边界错误被拒绝。资格失败就停止，不缩小范围或放宽阈值。

## 预测与裁决

完整预测逐点计算 `u=fx X/Z+cx`，宽度为两点 `u` 之差的绝对值。另记录两级
近似：`p_common=fx |ΔX|/Z_center` 保留朝向造成的横向分量但强制共同深度；
`p_simple=fx W/Z_center` 同时忽略转动和不等深。三个预测均由 CPU 和冻结输入
生成，不读取 renderer 的 `means2d`。

送入 renderer 的局部点和 B2W 位姿还要由独立矩阵运算回算到相机坐标；与设计
坐标的最大绝对差不得超过 `1e-5 m`。这个门用于发现坐标系或重复旋转错误。

- 五个标记几何和一个遮挡体后置正对照、三档距离、两背景，共 36 个图对：RGB 宽度相对完整预测均须
  在 0.5 px 内，才能接受“完整投影覆盖本设计网格”。不能缺测换取通过。
- `equal_depth` 与遮挡体后置的 12 个图对须同时符合简化预测。
- 其余 24 个可见但正对前提不满足的图对，实测 `±0.5 px` 区间须全部排除
  `p_simple`。居中 45° 的 6 个图对仍须覆盖 `p_common`；两个右偏转动和深度偏斜
  的 18 个图对须排除 `p_common`，以区分横向分量与逐点深度的作用。
- 6 个明确缺失和 6 个遮挡体前置图对须全部以精确错误
  `expected exactly two visible markers, found 1` 返回不可测。任意其他异常不能算
  通过。缺失控制的 6 次恢复检查必须逐像素一致。
- 若遮挡后仍测得两个标记，遮挡停止规则不通过；先查遮挡输入是否有效，再判断
  测量器，而不自动归因于 renderer 缺陷。

同一冻结配置在两个独立 Python 进程各执行一次，输出到 `run001` 和 `run002`。
比较 108 张/进程的原始 PNG 哈希、逐帧测量和裁决字段。所有 PNG 与数值一致才能
接受本机、该版本、该输入的跨进程重复性；这不是跨 GPU/驱动确定性证明。

预计每次主网格为 2 背景 × 3 深度 × 8 条件 × 2 明暗 = 96 张 RGB，缺失控制恢复
检查另有 12 张，共 108 张；两次共 216 张。
整体最高仍为 `down-weighted`，因为人工标靶和共同实现不能资格化普通车辆或现实。

## 运行与留存

```bash
env CUDA_HOME=/usr/local/cuda-12.1 TORCH_CUDA_ARCH_LIST=8.9 \
  PATH=/usr/local/cuda-12.1/bin:$PATH \
  /home/yawei/HUGSIM/.pixi/envs/default/bin/python \
  scripts/run_motion_observation_boundary_probe.py \
  --config configs/motion_observation_boundary_001.json \
  --output artifacts/motion_observation_boundary_001/run001
```

第二进程只改变输出目录为 `run002`。之后以冻结比较脚本核对两次结果。输出目录
必须不存在；保存环境、Git 状态、输入与脚本哈希、资格结果、所有 RGB、逐帧测量、
汇总和日志。任何失败保留原目录，不覆盖重跑。
