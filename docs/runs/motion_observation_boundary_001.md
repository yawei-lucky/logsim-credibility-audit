# HUGSIM 运动成像适用边界实验 001

2026-10-11。**实验已完成，所有预注册的科学裁决门通过；整体仍为
`down-weighted`。** 在冻结的人工双标记合同内，完整三维端点投影能够预测转动、
横向偏置和非等深条件下的 RGB 间距；简化的 `fxW/Z_center` 及共同深度近似在各自
前提失效时被明确排除。分析器也能在标记缺失或受控前置遮挡时停止输出宽度。

这回答的是“公式和测量器何时可用”，不是普通车辆重建、现实遮挡或 AD 行为是否
可信。它承接[标靶实验 001](motion_observation_probe_001.md)，并采用 NVIDIA／理想
[NuRec 联名报告](https://docs.nvidia.com/nurec/best-practices/scaling-neural-reconstruction.html)
中固定输入、受控比较、运行一致性和局部问题检查的思路；不把对方的工业结论或
阈值搬到本项目。

## 测量资格与执行门

GPU 渲染前，独立二维生成器执行 720 个通用图对和 30 个按实际投影位置、逐点
深度及不同投影大小生成的几何图对。**750/750 通过，最大绝对宽度误差
0.027223 px**。单标记、多标记和触边负对照分别以冻结的 `found 1`、`found 3`
和边界错误被拒绝。

送入 renderer 的局部点和 B2W 位姿另行回算到相机坐标，全部条件最大绝对误差为
`4.44e-16 m`，低于 `1e-5 m` 门。前后遮挡体的投影中心与左标记对齐，且深度
次序符合干预声明。

每个成功进程产生 48 个亮暗图对；缺失控制之后再渲染一次等深基线检查状态恢复，
总计 **108 张 RGB**。两个有效独立进程为 `run002` 和 `run004`。

## 完整投影与简化模型的边界

完整参考分别投影两个端点：

```text
p_full = |fx X2/Z2 + cx - (fx X1/Z1 + cx)|
```

同时保留两级近似：共同深度横向跨度 `fx|ΔX|/Z_center`，以及忽略转动和非等深的
`fxW/Z_center`。结果如下。

| 预注册检查 | 结果 |
|---|---:|
| 预期可测且实际测得 | 36/36 |
| 完整端点投影残差不超过 0.5 px | 36/36 |
| 最大绝对完整投影残差 | 0.035443 px |
| 等深及遮挡体后置条件覆盖 `fxW/Z_center` | 12/12 |
| 转动／非等深条件排除 `fxW/Z_center` | 24/24 |
| 居中 45° 条件覆盖共同深度横向跨度 | 6/6 |
| 端点深度不同的条件排除共同深度近似 | 18/18 |

下面的差值是实测中心值与近似预测之差；它们不是统计置信区间，但可以与冻结的
0.5 px 测量预算直接比较。

| 条件 | 与 `fxW/Z_center` 的最小差 | 与共同深度近似的最小差 | 最大完整投影残差 |
|---|---:|---:|---:|
| 居中 45° | 9.248 px | 0.007 px；全部仍被 0.5 px 区间覆盖 | 0.017839 px |
| 右偏 3 m、+45° | 7.149 px | 2.104 px | 0.026662 px |
| 右偏 3 m、−45° | 11.350 px | 2.077 px | 0.027527 px |
| 两端深度相差 12 m | 1.148 px | 1.148 px | 0.010064 px |

![完整投影与简化公式结果](../../artifacts/motion_observation_boundary_001/run002/boundary_results.png)

因此，本次结果没有发现完整三维点投影在该网格中的合同违反；它反而构成了两个
明确反例族：仅知道物理宽度和中心深度不足以处理目标转动，仅知道横向跨度和中心
深度也不足以处理端点深度差。这里拒绝的是简化模型的超范围使用，不是 HUGSIM
渲染器。

## 缺失与遮挡停止规则

同一遮挡体置于左标记后方时，**6/6** 图对仍检测到两个标记并满足完整投影；
移到前方时，**6/6** 都精确返回
`expected exactly two visible markers, found 1`，没有补造宽度。显式缺失控制同样
为 **6/6 `found 1`**。缺失后恢复原 opacity 的六次基线重渲染全部逐像素一致，
排除了临时状态泄漏。

![缺失与前后遮挡诊断](../../artifacts/motion_observation_boundary_001/run002/occlusion_diagnostic.png)

图中的差分列只显示由亮暗标记变化带来的像素。后置遮挡体条件保留两个差分点；
前置遮挡体与显式缺失条件都只剩右侧差分点。Gaussian 采用 alpha 合成，因此允许
的表述是“在冻结阈值下该特征不可测”，不是现实材料实现了完全不透明遮挡。

## 跨进程重复与失败运行

`run002` 与 `run004` 在同一主机、GPU、驱动、代码、配置和输入下由两个独立
Python 进程执行。比较结果为：

- 48/48 个完整测量记录逐字段一致；
- 108/108 张记录的原始 PNG SHA-256 一致；
- 所有可见性、模型覆盖和排除裁决一致。

这接受本机冻结环境中的跨进程重复性，不证明跨 GPU、驱动或软件版本确定性。

两个失败目录也保留：

1. `run001` 已完成全部渲染，但在写 `measurements.json` 时因 NumPy `bool_` 不能
   序列化而失败；上述窄修复后没有复用该目录。
2. `run003` 在模型载入前的 PyTorch／SymPy 多分派初始化中异常退出，没有开始
   HUGSIM 渲染。随后十个短的新进程均能初始化 optimizer，未能复现并隔离根因。

所以“每个完整新进程都能正常启动”这一具体运行可靠性主张为 `rejected`；异常
机制本身只有 `down-weighted`，不能归因于 HUGSIM，也不能从一次事件估计失效率。
它说明后续批量验证仍需保留启动健康门、失败产物和重试身份。

## 裁决与证据边界

| 主张或诊断 | 裁决 | 范围 |
|---|---|---|
| RGB 宽度测量器通过有限边界网格及指定负对照 | `accepted` | 750 个解析图对 |
| 完整端点投影预测可见标记宽度 | `accepted` | 两背景、三深度、六个可见条件；36 图对 |
| `fxW/Z_center` 可直接用于本设计中的转动或非等深目标 | `rejected` | 24/24 排除；模型前提边界诊断为 `accepted` |
| 共同深度横向跨度可用于本设计中的端点深度差 | `rejected` | 18/18 排除；模型前提边界诊断为 `accepted` |
| 缺失或前置受控遮挡时保留不可测状态 | `accepted` | 两背景、三深度；12/12 精确 `found 1` |
| 成功运行的同机跨进程 RGB 与数值可重复 | `accepted` | `run002` 对 `run004`，108 张 RGB |
| 修复后的所有完整进程均可正常初始化 | `rejected` | 三次完整尝试中 `run003` 在渲染前失败 |
| 整体 segment | `down-weighted` | 人工标记与同源渲染不能资格化现实车辆、真实相机或 AD 任务 |

本实验提高了方法的诊断能力：当简化模型失配时，完整投影仍通过，故可以把错误
定位到公式前提；当特征不可见时，分析器不输出伪数值。它没有增加真实—仿真等效
证据，也没有给出任何驾驶安全阈值。
